# UI implementation conventions

Read this guide before changing frontend behavior. Core security, architecture, and verification rules remain in [AGENTS.md](../../AGENTS.md).

## Shared components and presentation

- Use locally hosted Inter in the app/authentication UI, Shippori Mincho for the public brand, exact AgentZuno casing, and #818CF8 brand surfaces in both themes. Preserve device theme preference, accessible foregrounds, reduced motion, and forced colors.
- Delete/removal confirmations use the shared ConfirmationDialog: stacked themed fields, exact-name instructions below the input when required, consistent spacing, and Cancel followed by the confirmation action aligned right. Keep Cancel initially focused and preserve Escape dismissal and server checks.
- Reuse Icon, Dropdown, ReferenceLookup, MultiSelectLookup, ValidatedForm, RecordTable, Breadcrumbs, Skeleton, WorkspaceModal/confirmation controls, and record components. No native selects or duplicated control styles. Icons/badges never flex-shrink; icon-only buttons need accessible names.
- Shared single-line controls are 44px tall except compact sidebar/toolbar variants. Align search/buttons/tabs on one row where practical; keep sections full width with min-width:0/border-box. Use 20px before form actions, 12px between related buttons, and wrapping on small screens.
- Boolean form settings use switches centered beside labels; checkboxes are for selection lists. Routing Instructions belongs directly below an enabled Assignment Group switch. Show small secondary Required/Optional text immediately after field labels instead of asterisks; preserve native required/ARIA and server validation.
- Read-only and disabled references have distinct full-control backgrounds, including icons, with transparent inner inputs. Single/multi references show an Info link per selected record opening the real scoped record in a new tab; typed text is not a selection.
- Validate saved forms on submission only; clear an existing corrected error on input/change/key-up. Preserve error summaries, ARIA hints, and first-error focus. Chat uses a plain no-validate composer with bounded nonempty input and server validation.

## Navigation, lists, and loading

- All roles land on Dashboard, which combines My Requests and role-eligible My Work. Legacy list routes redirect there. Keep Dashboard, Chat, Inbox when eligible (assignments/approvals/mentions), Knowledge in the sidebar. Label Data Tables and Users & Groups consistently. Docs belongs in the profile menu, not workflow actions.
- Keep the shared sidebar/provider/theme/profile mounted across navigation. Authorization/cache identity is account/workspace/effective-role scoped. Never flash denial before access resolves or expose protected links before authorization.
- Expanded sidebar Create centers a compact icon/text group. Collapsed controls stay 32px square, with inset hover surfaces and unclipped hover/focus tooltips. Brand hover has no background; profile hover does. On phones use a top bar with drawer left and Inbox/profile right; overlay the expanded menu without its redundant toggle.
- Scope app overlays to content outside the sidebar, center dialogs, lock background scrolling, and retain sidebar interaction for search. Dismiss prior overlays before opening another. Clear route-scoped toasts/timers on navigation.
- Default standard pages to 1120px content width; initial Chat remains centered at 800px. Full-height split editors fill the content viewport, with independent pane scrolling and no HTML scrolling. Resizable divider/header tabs stay keyboard/touch accessible; tabs scroll horizontally without visible header scrollbars.
- Breadcrumbs use actual scoped ancestors, human labels, current-page ARIA, and context-preserving links. Compact record titles/actions align centrally; Back uses a left arrow. Avoid redundant headings and decorative help text.
- Lists share RecordTable styling, whole-row navigation, accessible sort headers/arrows, and Updated at the far right. No separator between search and rows. Bottom numbered pagination has navigation left, page/count center, compact record-limit dropdown right; exports live in a matching-height ellipsis action.
- Cards and panels use neutral outlines without decorative colored top/left borders. Preserve accessible focus indicators and semantic status labels.
- List view, filter, and sort controls use compact icons with accessible names/tooltips. Sorting and direction share one menu.
- Shared record lists default to cards with a Cards/Table toggle. Remember the choice per account/workspace/module, preserve sorting/pagination in both modes; show selection checkboxes only in tables, place selected counts and bulk actions directly above Select All in a dedicated left-aligned row, and use restrained module-specific presentation with actual record data. Do not invent progress metrics. Dashboard titles and refresh/actions share one header row; consolidate list exports into that dashboard's single secondary-actions menu.
- Empty unfiltered lists show one contextual message/action without search/table/pagination chrome. Keep filters when an entered query has no matches and tabs available for switching. Filtered empty, error, and loading states are distinct.
- Below 700px, lists become labeled panels retaining selection, search, sort, pagination, and actions. Use compact 12px side padding and consistent dark/purple checkboxes. Tables/code in docs can scroll within their own region, never widen the document.
- Every explicit record/configuration save shows a success toast only after server confirmation and an error toast on failure, preserving edits for retry. Form replacement/refetch on the same route must not suppress feedback; navigation clears notices and suppresses late responses from the previous route. A confirmed save that redirects may explicitly target its destination route for one success notice; unrelated navigation must still clear it.
- Fetch tabs/accordions/dialog content only when opened. Render static authorized shells, controls, and labels immediately; put content-shaped skeletons exactly where dynamic content belongs. On tab changes, do not flash another tab's stale table; on same-view refresh, preserve cached content and stable IDs. Use a short opacity reveal without layout shifts.
- Background polling preserves draft inputs, focus, selection, expanded state, and scroll. Pause while hidden and stop on unmount. Reconcile records by ID; never overwrite an in-progress approval rejection comment.

## Records and conversations

- Non-chat tasks/groups/data records start as read-only details with a real title, stacked labels and values, and a soft description block. Edit switches one form with one Save/Cancel set while preserving field order. All form fields use labels above their controls at every screen size, matching workflow settings; reference controls and multiline fields use the same full-width alignment. Edit/create Description aligns with neighboring fields and has no separately padded background. Sections/fieldsets must not shrink to their labels. Omit redundant record-name “Details” headings from forms; retain meaningful sections such as Permissions, Workspace Access, and Membership.
- Creation/editing of users and other full records belongs on dedicated routes, not modals. Use RecordHeader for title/actions and RecordForm/RecordField for schema-driven records. Order sections as core details, operational settings/access, then membership/related records; keep labels aligned and sections full width. Keep authorization, persistence, and optimistic versions in the existing services rather than the renderer.
- Desktop tables use flat rows, subtle horizontal dividers, muted headers, and single-line cell text. Keep intentional title/subtext and Inbox detail stacks; mobile uses labeled cards. DashboardToolbar owns refresh/filter alignment and working secondary links in ActionMenu. Do not add decorative filters or display controls without implemented behavior.
- Show Comments and Work Notes tabs by permission even when empty. Work Notes remain staff-only. Use shared MentionTextarea, safe text rendering, author avatars, and timestamps. Request tasks are single-border cards, not nested outlined tables; show due dates and a navigable originating-request reference.
- Record/conversation tabs use subtle purple pills without heavy underlines or strip borders. Secondary actions stay visible in either theme. Right-panel action labels are left aligned; keep actions in that panel's header.
- Profile identity/cover/avatar remain visible and unclipped. View/edit use identical grids; centered far-right pencils or double-click enter whole-form edit. Keep own name editable/required as permitted, picture removal, safe upload limits, and allowlisted cover themes. A loading/unknown avatar uses a user icon, never '?'.
- Preserve unsaved app edits through the custom centered navigation confirmation; Cancel keeps drafts and success clears guards. Use browser unload protection for refresh/close. Do not show app unsaved-edit dialogs on Login/Register.
- Support replies have no bubble; user bubbles are slim and theme aware. Composer stays visually enabled while generating, with Send disabled/bottom-right in multiline input and consistent bottom padding. Do not add a Zuno field label or robot heading.
- Scroll newly sent user messages into view. A new response may receive one small capped reveal after sending, cancelled by reader interaction. Never follow streamed chunks/forms or move a reader who scrolled upward. Request-panel scroll resets only for a different request; existing request conversations open at their latest message.
- Forms appear after their response, remain chronological, become read-only after idempotent submission, and link to the saved request. A chat with multiple requests uses a dedicated full-width selector above right-panel actions. No standalone New Request form/global action.
- Keep message-shaped history skeletons inside transcripts, static composers visible, and no stale history/processing state across conversation IDs. New Chat belongs in the shared top chat toolbar, not History or bottom footers.
- Activity shows live processing/completion once per step; combine response generation phases. Put Finished with its time at the far right inside Activity; do not append Complete to replies. Show a collapsible tool list with outcomes/time, never raw arguments/private reasoning.
- Global search loads only up to five reauthorized recent references on open, then queries asynchronously after typing. Header/input stay fixed while only results show skeletons; reject stale search responses. Search permitted request answers/tasks as well as other supported records.

## Knowledge, marketing, and Docs

- Knowledge uses a full-height, resizable folder explorer and a content pane for every role, with permission-based management actions. Retired tabbed list URLs and base detail URLs open this interface. Base cards show only their title and description. Article explorer rows reveal an authorized edit pencil in a translucent right overlay on hover/focus; reader edit actions share the breadcrumb row. Top-level topics use compact cards; subtopics within a topic use wrapping navigation pills above the articles, with matching loading placeholders. Folder nodes are bases, topics (up to three levels), and articles; selected articles read in the content pane. Bases/topics edit in a right-side panel with stacked fields, unsaved-change protection, and confirmed deletion of empty folders; General stays available to all workspace members and cannot be deleted. Creation uses a quick dialog; articles keep their dedicated reader/chat editor. Read-only articles show body content in the wider left column and attachments in a smaller right column, stacked on mobile, without reader tabs. Base context, article/topic filters, and permissions remain explicit.
- Knowledge has a neutral divider under its header. The explorer header replaces its label with a compact search across permitted bases, topics, and articles and keeps Add Knowledge Base (for administrators), Refresh, and Collapse All visible with tooltips. Empty folders reveal an outlined Add article action on hover/focus, always visible on touch, preserving that folder’s base/topic. Create topics/articles through compact folder actions revealed on hover or keyboard focus (always visible on touch devices). Keep the page header free of a duplicate secondary-actions menu; editable bases/topics show a pencil in their folder row on hover or keyboard focus. Use book icons for bases, folder icons for topics, compact article labels, and shallow tree indentation. Explorer actions use immediate hover/focus tooltips that stay outside the scroll clipping region. Preserve that folder's base/topic context, hide Add Topic at depth three, and persist the authenticated workspace on new bases.
- Article authoring shares the split chat/editor layout. Automatically open proposed review previews once per finished response, require approval before persistence, then redirect new articles to their saved editor. Manual Publish is not another AI-proposal approval; only offer changes when unpublished differences exist. No read time or 'Your workspace article' text.
- Reports has one selector left and date/transparent refresh controls right, without duplicate titles. My Work is personal; My Team follows group access. All dynamic report content loads lazily.
- Keep the marketing hero close to the navigation, with 48px desktop and 32px mobile top padding and desktop copy aligned with the demo. Public headers remain sticky in the document flow, hide after sustained downward scrolling, and return on upward scrolling or keyboard focus. Reveal marketing text in whole blocks without per-line stagger.
- Marketing illustrates behavior; it never executes live workflows. Hero demos advance only the active panel, freeze the background panel, and start its sequence when swapped forward. The workflow example reveals a submitted prompt, a short assistant reply, then whole step panels with a restrained stagger. Start loops only when visible, hold completed states long enough, and respect reduced motion. Reveal complete messages, never type characters. Keep panel shells visible and heights stable through repeats; fade/reset inner content only and scroll overflow. Touch gestures must continue to scroll the page.
- The homepage request lifecycle uses sticky cards that stack through normal page scrolling and release within their section. Visual details animate once when visible. Reduced motion uses an ordinary static list; never capture wheel or touch scrolling.
- Public Docs are focused guide pages using the shared registry, metadata, canonical links, and sitemap. Preserve old anchors, open new pages at top, and scroll only heading links. No public Sign In/Get Access actions. Mobile Browse Docs exposes categories and section jumps; index highlighting follows scroll. Use sanitized guides, bounded code/table scrolling, real fictional-fixture screenshots, and external links in new tabs.

- Knowledge headers span the full content width; article lists show authorized creator/owner names with circular avatars and real updated dates. Never infer an author when only ownership is known. Data records use a full-height form/activity workbench with the form on the left and Comments, Work Notes, and Related records tabs on the right, shared resizable divider and independently scrolling panes. Show fields in schema order without group headings, separators or section navigation. Data Table descriptions align with other fields in both details and edit mode, without a separately padded description block. Keep breadcrumbs and actions vertically centered in one fixed header without a duplicate visible record title or Properties heading, and mobile Form/Activity switches.

- Source-managed Data Table records keep Edit disabled with a hover/focus tooltip directing users to their original record; preserve the authorized Open Original Record link. Label table design actions Edit Table.
